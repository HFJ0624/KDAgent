3. Variable types;
4. Time-series evidence such as raw / reconstructed / residual / anomaly score;
5. Upstream-downstream influence relationships among variables;

Below is the Top-10 candidate root-cause variables generated by the numerical RCA model. Each candidate variable may include:

* variable_name: the real industrial variable name, e.g., FIT101, LIT101, P302
* variable_type: the variable type, e.g., continuous or state

* time_series_evidence: evidence within the time window such as raw, reconstructed, residual, score

Please complete the root cause analysis based on this information.

Important Analysis Principles:

1. Do not simply select the variable with the highest anomaly score.
   A high-score variable may only be a downstream variable affected by the root cause, not the actual root cause.

2. You must consider the variable type.

   * For continuous variables (e.g., flow, level, pressure, water-quality sensors), focus on:
     - Trend changes (rising/falling trends)
     - Residual magnitude (sustained deviation or sudden spikes/drops)
     - Reconstruction error (the deviation between raw and reconstructed)
     - Fluctuation pattern (whether it is stable or oscillates violently)

   * For state variables (e.g., valves, pumps, switches), focus on:
     - State switching (whether it switches from a normal state to an abnormal state)
     - Abnormal persistence (whether it stays abnormal)
     - Whether the state is consistent with the upstream/downstream sensors

3. You must analyze using time-series evidence.
   For each candidate variable, carefully examine:
   * raw value: the actual measured value
   * reconstructed value: the model-reconstructed value
   * residual: the residual (raw - reconstructed)
   * anomaly score: how the anomaly score changes over time
   * temporal trend: the trend within the time window

4. You must distinguish the root cause from propagation effects.
   The root cause variable is more likely to:

   * Be a state variable that, after an abnormal switch, causes changes in several downstream sensors;
   * Be an upstream key variable that, once abnormal, triggers a chain of anomalies in downstream processes;
   * Have a persistently abnormal residual that can also explain the anomalies of other candidate variables;
   * Exhibit an earlier anomaly onset time (temporally prior).

5. Reason with SWaT process relationships.
   For example:

   * An abnormal valve may affect flow;
   * An abnormal pump may affect downstream flow, level, or pressure;
   * An abnormal level may be related to influent flow and outlet pump state;
   * A water-quality sensor anomaly may be caused by changes in an upstream treatment process.

6. The final root cause must be selected from the Top-10 candidate variables.
   It is strictly forbidden to output any variable not in the candidate list.

Output Requirements:

* predicted_root_causes: at most 5 variable IDs, all from the Top-10 candidates, sorted from most to least likely root cause.
* primary_root_cause: the single most likely root-cause variable ID, which must be the first element of predicted_root_causes.
* root_cause_name: the real name of the root-cause variable (e.g., LIT101, FIT101).
* confidence: a confidence score between 0 and 1. It should be higher when the evidence is clear and lower when uncertain.

* reasoning: an overall explanation of why this variable was chosen as the root cause.

* inference_process: a complete and verifiable record of the reasoning process. It must be an array of exactly 4 objects, strictly ordered by the following stages:
  1. Candidate evidence comparison: compare the anomaly scores, residuals, variable types, and anomaly patterns of the main candidates;
  2. Temporal precedence judgment: determine which anomalies started and persisted earlier;
  3. Process propagation analysis: infer the possible upstream root cause and its downstream propagation path;
  4. Final root-cause decision: synthesize the evidence to determine the ranking and state the key exclusion justifications.
  Each object must include step, stage, analysis, evidence_variables. analysis should provide a decision summary based on the input evidence, and evidence_variables must all come from the Top-10.

* numerical_evidence: describe numerical evidence such as anomaly scores, ranks, and residual magnitudes. For example: "The variable has an anomaly score of 0.92, ranks 2nd in the Top-10, and has a mean absolute residual of 0.45".

* temporal_evidence: describe how raw/recon/residual/score change within the time window. For example: "The residual starts to deviate persistently from zero at t=10, and the raw value shows a sudden increase at t=15".

* type_aware_reasoning: explain whether the variable is continuous or state, and why the corresponding type-specific logic was applied. For example: "The variable is of continuous type, so I focus on the persistence of its residual trend and reconstruction error".

* process_relation_reasoning: explain how this variable affects other candidate variables through the process flow, and which variables look like downstream responses. For example: "This variable is upstream in the process; its anomaly may influence downstream variables V33 and V45 through material transport".

* why_not_other_candidates: explain why other variables with higher or similar scores were not chosen. For example: "Although V19 has the highest score, it is more likely a downstream response to the V1 anomaly, and its residual pattern shows a follow-through change".

* evidence_variables: the key evidence variables supporting the judgment; they must come from the Top-10 candidates.

* uncertainty_analysis: explain the sources of uncertainty in the judgment. For example: "Due to the lack of direct process knowledge, the possibility that V19 is an independent root cause cannot be completely ruled out".

* is_valid_prediction: a boolean indicating whether the prediction is reliable. Set to false when there is clearly contradictory evidence.
